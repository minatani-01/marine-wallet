# 賃貸さがし（0075）

マスターだけが使える画面（`/rent`）。指定した駅**すべて**から徒歩◯分以内にある
建物を出す。

## なぜ作ったか

SUUMO などの検索は「いま空いている部屋」の一覧である。住みたい場所が決まっていても、
そこに**建っている**建物は分からないし、空室が出た時点では間に合わないこともある。

駅を複数入れたときの扱いも違う。既存のサービスは「A駅またはB駅から徒歩10分」の OR に
なるため、片方からしか歩けない部屋が並ぶ。ここでは AND にして、全部の駅の徒歩圏が
**重なったところ**だけを範囲にする。

空室かどうかは見ない。建っているものを並べて、あとは管理会社や募集情報で確かめる。

## 作り

```
駅を入れる（Places Text Search）
   ↓
徒歩圏を重ねて範囲を出す（lib/rent.ts / 純関数・端末の中で計算）
   ↓
範囲の中の建物を集める      1. OpenStreetMap（Overpass API）… 輪郭をまとめて
   ↓                        2. Google Places（Nearby Search）… 名前を補う
徒歩時間を実測（Routes API / Compute Route Matrix・徒歩）
   ↓
全部の駅の条件を満たすものだけ残す
```

| ファイル | 役目 |
| --- | --- |
| `lib/rent.ts` | 円の重なり・徒歩分の換算・並べ替え・突き合わせ（純関数） |
| `lib/rent-osm.ts` | Overpass への問い合わせ |
| `lib/rent-google.ts` | Places Nearby と Routes の徒歩時間 |
| `app/api/rent/stations/route.ts` | 駅を名前で探す |
| `app/api/rent/buildings/route.ts` | 範囲の中の建物を返す（上の流れを束ねる） |
| `components/rent/RentClient.tsx` | 画面 |
| `components/rent/RentMap.tsx` | 地図（輪・重なりの塗り・建物） |

## 必要な設定

`GOOGLE_MAPS_SERVER_KEY` の鍵に、Google Cloud 側で次の API を有効にしておく。

- **Places API (New)** … 駅の検索と建物名（すでに場所検索で使っている）
- **Routes API** … 徒歩時間の実測（**この機能で新しく要る**）

鍵の「API の制限」にも Routes API を足すこと。足りないと、徒歩時間が実測されず
直線距離の概算のままになる（画面には「概算」と出る）。

Overpass API は鍵も登録も要らず、費用もかからない。寄付で運営されている公開サーバーなので、
範囲を四角で切って1回だけ、件数の上限付きで呼ぶ。

OSM のデータは ODbL で、**出典の表示が条件**になっている。画面の下に
「© OpenStreetMap contributors」をリンク付きで出している。消さないこと。

## まわりの施設（0077 / 0078）

コンビニ・薬局・歯科・内科・美容院が、建物から徒歩◯分以内に**あるかどうか**を一覧に出す。
**建物は落とさない**（0078）。歯科が無いからといって住めないわけではない。何があって何が
無いかが並んでいれば、見るほうが決められる。チェックは「どれを見るか」の指定。

- **出どころは OSM。** 建物を取るのと同じ1回の問い合わせでまとめて取る（`shop=convenience`
  `shop=chemist` `shop=hairdresser` `amenity=pharmacy|dentist|clinic|doctors`）。
  `shop=beauty` はネイルやエステも入るので、名前に「美容室」「ヘア」とあるものだけ美容院に数える。Google に聞くと種類ごと・円ごとに
  呼ぶことになり、1回の検索で20回を超える。費用は増やさない。
- **四角は建物より900m広く取る。** 範囲のふちに建つ建物は、外にある店がいちばん近い。
- **種類は名前も見て決める**（`lib/rent-osm.ts` の `facilityKind`）。日本のクリニックは
  `healthcare:speciality` が入っていないことが多く、代わりに名前に「内科」「歯科」と
  書いてある。風邪で行くところを探しているので、眼科・整形外科など専門科だけの医院と
  動物病院は外す。
- **出し分けは画面の中だけ。** 施設までの分数は検索のときに全種類ぶん持ち帰るので、チェックを
  変えても外へ聞き直さない。
- 施設までの時間は**直線距離からの概算**（建物から種類ごとに最も近い1軒まで）。
- OSM が取れなかったときは全部「なし」と出し、その旨を画面にも出す。

## 飲食店（0079）

「★3.0以上の飲食店が、建物から徒歩◯分以内にあるか」をチェックで足せる。

- **ここだけ出どころが Google。** 口コミの評価は Google にしかなく、OSM は店の有無しか
  持っていない。「近くに店がある」ではなく「入りたい店がある」かを見たい。
- **頼まれたときだけ聞く。** チェックを入れて「この範囲の建物を探す」を押したときに調べる。
  毎回聞くと1日に数回しか探せなくなる（評価まで受け取ると課金の区分が一段上がる）。
- 星は 3.0 / 3.5 / 4.0 から選ぶ。切るのは Google 側（`minRating`）に任せる。1回に20件しか
  返らないので、こちらで受け取ってから捨てると、条件に合う店が入らない。
- 出すのは**いちばん近い1軒**と、その評価。

## 築年数と、物件名での検索（0082）

**築年数は無料で引けるデータに入っていない。** 公的データ（不動産情報ライブラリ）は建築年を
持つが物件名が無く、所在も町丁目まで。物件名を持つサイト（SUUMO など）には公式 API が無い。
住所で突き合わせようにも、同じ町丁目に数百棟あるので特定できない。

できるのは次の2つだけ。

1. **OSM の `start_date` を読む。** 入っていれば「築◯年」と出す。日本では稀にしか入って
   いないが、取るのに費用はかからない。書き方が揺れる（`1998` `1998-04` `~1998` `C19`）ので、
   年として読めるものだけ採る。分からないものは何も出さない。「築0年」と書くと新築だと
   思われる。
2. **物件名で各サイトを開くリンク。** SUUMO・HOME'S・Google を名前で開く。掲載があれば
   築年数・構造・戸数がその場で分かる。サイト内の検索URLは作りが変わると壊れるので、
   `site:` を付けた検索で開く。

今年は日本時間で切って画面へ渡す。UTC のままだと、大晦日の夜に築年数が1年ずれる。

## 駅の組み合わせを残す（0080）

名前を付けて `rent_searches` に残す。端末を変えても、キャッシュを消しても残る。

- いま入れている駅は端末の `localStorage` に置き、**名前を付けて残した組だけ**を DB に持つ。
- 同じ名前は上書き（`(user_id, name)` に一意制約）。押し間違えて同じ組が並ぶと、どれが
  新しいか分からない。
- 駅は jsonb でまとめて持つ。1駅1行にすると並び順と組を指す列が要るが、組ごと丸ごと
  読み書きするだけなので分ける意味が無い。
- RLS は `user_id`。master だけの画面だが、見えないことと読めないことは別。

## 使った回数の数え方（lib/api-budget.ts）

| 名前 | 数えるもの | 1日 | 1か月 |
| --- | --- | --- | --- |
| `places_search` | 駅の検索（1回） | 50 | 1,000 |
| `places_nearby` | 建物名を聞いた回数 | 60 | 1,200 |
| `places_rating` | 飲食店を聞いた回数（評価つき＝課金区分が上） | 40 | 800 |
| `routes_walk` | 徒歩時間の**element 数**（駅数 × 建物数） | 600 | 8,000 |

徒歩時間だけ呼び出し回数ではなく element で数える。1回の呼び出しで何十件ぶんも課金
されるため、回数で数えると上限が100倍ゆるくなる（`spend_api_calls` / 0074）。

目安: 2駅 × 建物40件の検索1回で、`routes_walk` を80使う。1日7回ほど、1か月100回ほど。

## 分かっていること・限界

- **徒歩時間**は Google の徒歩ルートでの実測。測れなかったときは直線距離 ÷ 80m の概算に
  落ちて、画面に「概算」と出る。不動産広告の表示も80m＝1分なので、概算でも広告とは
  揃う（ただし広告は道路距離、こちらは直線距離）。
- **建物の網羅**は OSM に入っているものが土台。入っていない建物は出ない。
- **名前**は OSM に無ければ Google で補う。それでも分からないものは「名前の分からない
  建物」として地図にだけ出す。
- 候補が40件を超えるときは、近いものから40件だけ調べる（実測の費用と待ち時間のため）。
  画面にその旨を出す。徒歩時間を短くすれば全部入る。
- 条件（駅と徒歩時間）は端末の `localStorage` にだけ置く。DB に持たせると、相手の画面
  からも「引っ越しを考えている」ことが見える。
